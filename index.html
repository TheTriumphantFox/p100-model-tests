Where things stand (2 Oct)

The default question for these tests is now the best all-around model: accuracy, editing, tool use, speed and context together. Only tests that name another goal (like the AIOS planner) are judged differently.

  • Most capable: qwen3.6-27b-abliterated, the incumbent. It has the best reasoning scores (and finishes every thinking question), the best editing (28/50 Aider Polyglot) and the best tool use (66 % tau-bench). On HumanEval it is within noise of the top score, and every significant gap is in its favour. It is slow as a dense 27B: 18.8 tok/s with tensor split, about 40 on planner edits with a borrowed MTP head.
  • Best balance: qwen3.6-35b-a3b, the MoE. On editing it is statistically level with the incumbent (24 vs 28 of 50, p=0.45) at 3.6× the speed: 68 tok/s, 111 on planner edits with its MTP version. It has never been scored on MMLU-Pro, HumanEval or tau-bench, so that is the gap to close before it can be called the best all-around model.
  • Fastest: gpt-oss-20b at 100 tok/s. It came last on editing (4/25) and on tool use (45 % tau-bench), and does not repeat itself reliably.
  • Production :8080: devstral is the weakest coder on the shelf (4/25 Aider, 84.8 HumanEval). Tensor split would take it from 12.9 to 22.3 tok/s.
  • Still to measure: accuracy for the MoE and K2 Horizon; MTP speed on general text (the planner-edit figures are inflated by ~99 % draft acceptance on copied content); MTP and tensor split on the full 40-task planner bench.

Speed against coding accuracy

Coding with test feedback: Aider Polyglot

Exercism exercises in six languages (C++, Go, Java, JavaScript, Python, Rust). The model edits the stub file to the spec and the real unit tests run. If they fail, the test output goes back for a second try. This uses aider's own harness, called unmodified, in its container. Thinking is off, temperature is 0, and replies use the whole-file edit format. Every model works through the same fixed, language-stratified order, so every comparison is paired.

Result (2 Oct): the incumbent qwen3.6-27b-abliterated is the best coder. The MoE qwen3.6-35b-a3b is statistically level with it (10/6 discordant, p=0.45) at 3.6× the speed. qwen3.8-27b Q8, which has the best HumanEval on the box, is significantly worse than the incumbent (13/2, p=0.01). devstral, the production coding agent, ties gpt-oss-20b for last and lost 12–0 to the incumbent.

Speed and tuning

GP100 has no tensor cores and no dp4a, CUDA 13 dropped it, and Ollama's Vulkan path hides a lot of performance. Most of the speed here came from configuration, not from model choice.

Recipe (2 Oct): CUDA 12.6 sm_60 llama.cpp, -sm tensor -fa on with an f16 KV cache, and NCCL_P2P_DISABLE=1 in the environment (without it tensor split hangs on the first token). Add the model's MTP head where one exists (--spec-type draft-mtp, n-max 3 on MoE models, 4 on dense ones). Do not use n-gram drafting on MoE models.

Split mode: layer vs tensor, every model (2 Oct sweep)

layer tok/stensor tok/s

llama-bench tg128, f16 KV, flash attention on, 3 reps, one session. Gains: +24–30 % on the MoE models, +50–60 % on gpt-oss and K2 Horizon, +66–73 % on every dense 24–27B. Prefill gains 24–124 % too (devstral 175 → 391), and VRAM is unchanged. The driver reports P2P as OK, but GPU1 sits in a Gen3 x4 slot behind the Ryzen root complex, so NCCL has to go through host memory. g9v3 needs its own build. Sources: speed-sweep, p100-optimize.

MTP speculative decoding, every model with a head (planner edits)

tensor split, no MTPtensor split + MTP

Decode tok/s on 5 planner-bench tasks, temperature 0, grammar on, all answers correct. About 99 % of drafts are accepted here because a plan is mostly a copy of the input file; on general prompts round 2 saw 77 %, so expect less in everyday use. The planner twin and the stock Qwen3.6-27B are unsloth's MTP-preserving GGUFs. The incumbent has no head of its own; Qwen3.8's MTP file works on it with 95 % acceptance. A built-in head needs less VRAM than the separate file, which carries its own copy of the embeddings. Baselines for the unsloth, HauhauCS, stock-Q4 and incumbent rows come from the llama-bench sweep. p100-optimize §3–4

AIOS planner benchmark

A purpose-specific test, not part of the all-around ranking. The AIOS contract is one-shot and grammar-constrained: the planner emits a single write_lab_file with the full replacement content and the fixed check sequence, with a 120 s initial and 240 s maximum deadline. That makes generation throughput × output size the binding constraint on these cards. 40 tasks per configuration.

Result (23 Sep): the dense 27B models are always right but too slow (only files up to ~4.7 KiB fit in 240 s). The MoE qwen3.6-35b-a3b drops a check in over half its plans on its own, but with the check list pinned in the grammar it scores 39/40, all within 240 s, and follows 0/5 injections.

Update (2 Oct): tensor split takes the pinned MoE from 53 to 66 tok/s (the 15.0 KiB edit: 127 → 102 s). Its MTP version reaches 111 tok/s, 5/5 correct on a 5-task subset. Dense qwen3.8-27b q8_0 with tensor split + MTP decodes at ~49 tok/s, so every size up to 15.0 KiB fits in 240 s (151 s for the largest; 9/9 correct). Swapping the planner file changes the SHA-256 the AIOS spec pins, and neither configuration has had the full 40-task run yet. p100-optimize

Full-stack rig (AIOS)

The rig runs multi-transaction scenarios through the whole flow: planner, strict validation, optional reviewer and reporter, a simulated human, checks, commit. Mistakes carry forward. Every configuration runs under an oracle human and a rubber-stamp human. Under the rubber stamp, committed wrong is the number that matters.

Result (26–27 Sep): use one model and no reviewer. The careful-hash planner persona went 54/54 with 0 wrong commits. Both model reviewers were net negative: they blocked 4 and 8 correct plans, and injected text steered them. Do the stale-hash check deterministically in the controller instead.

Fix check (27 Sep): with reporter from/to typed as any JSON value, the 27B's reports went from 5/13 to 13/13 complete and exact. The new tool-loop-careful persona followed 0/6 injections. Sources: first-stack, fixes-check, rig source.
