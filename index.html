Model scoreboard

Every model that loads on the CUDA build, with identical questions for each. Reasoning is 70 MMLU-Pro questions (5 per category × 14). Coding is all 164 HumanEval problems. Seed 42, temperature 0. Click a column header to sort.

Result (21 Sep): keep the incumbent qwen3.6-27b-abliterated. It has the best score on every accuracy test and is the only model that finishes every thinking question. Every statistically significant gap (McNemar exact, p<0.05) is in its favour. The one exception is speed, where the MoE models are 4–6× faster.

Update (1 Oct): the incumbent at higher quants, its own abliteration at Q8_K_P and Unsloth's stock Q8_0, scored up to 3 questions better on reasoning and 1–2 worse on coding. No gap is resolvable (every p ≥ 0.25). Both cost all but ~16–32k of the context headroom, so both were deleted and the Q5 stays.

Update (2 Oct): HumanEval is saturated (92–97.6 % across the shelf) and its ranking does not hold when models have to edit files with test feedback. On Aider Polyglot the incumbent is still first, but qwen3.8-27b Q8 drops from first to third. See Coding.

Speed note (2 Oct): the speed column is layer split. Tensor split, which works once NCCL peer-to-peer is disabled, adds ~25 % to the MoE models and ~70 % to the dense 27Bs. See Getting the most out of Pascal.

Coding with test feedback: Aider Polyglot

Exercism exercises in six languages (C++, Go, Java, JavaScript, Python, Rust). The model edits the stub file to the spec and the real unit tests run. If they fail, the test output goes back for a second try. This uses aider's own harness, called unmodified, in its container. Thinking is off, temperature is 0, and replies use the whole-file edit format. Every model works through the same fixed, language-stratified order, so every comparison is paired.

Result (2 Oct): the incumbent qwen3.6-27b-abliterated is the best coder. The MoE qwen3.6-35b-a3b is statistically level with it (10/6 discordant, p=0.45) at 3.6× the speed. qwen3.8-27b Q8, which has the best HumanEval on the box, is significantly worse than the incumbent (13/2, p=0.01). devstral, the production coding agent, ties gpt-oss-20b for last and lost 12–0 to the incumbent.

Planner benchmark

The AIOS contract is one-shot and grammar-constrained. The planner emits a single write_lab_file with the full replacement content and the fixed check sequence, with a 120 s initial and 240 s maximum deadline. That makes generation throughput × output size the binding constraint on these cards. 40 tasks per configuration.

Result: the dense 27B models are always right but too slow (only files up to ~4.7 KiB fit in 240 s). The MoE qwen3.6-35b-a3b drops a check in over half its plans on its own, but with the check list pinned in the grammar it scores 39/40, all within 240 s, and follows 0/5 injections.

Update (2 Oct): with tensor split the pinned MoE planner decodes at 66 tok/s instead of 53 (the 15.0 KiB edit: 127 → 102 s). Dense qwen3.8-27b q8_0 with tensor split + its MTP head decodes at ~49 tok/s with ~99 % of drafts accepted, so every size up to 15.0 KiB now fits in 240 s (151 s for the largest). That run covers 9 of the 40 tasks (9/9 correct); a full 40-task run is still to do. p100-optimize

Full-stack rig

The rig runs multi-transaction scenarios through the whole flow: planner, strict validation, optional reviewer and reporter, a simulated human, checks, commit. Mistakes carry forward. Every configuration runs under an oracle human and a rubber-stamp human. Under the rubber stamp, committed wrong is the number that matters.

Result (26–27 Sep): use one model and no reviewer. The careful-hash planner persona went 54/54 with 0 wrong commits. Both model reviewers were net negative: they blocked 4 and 8 correct plans, and injected text steered them. Do the stale-hash check deterministically in the controller instead.

Fix check (27 Sep): with reporter from/to typed as any JSON value, the 27B's reports went from 5/13 to 13/13 complete and exact. The new tool-loop-careful persona followed 0/6 injections. Sources: first-stack, fixes-check, rig source.

Getting the most out of Pascal

GP100 has no dp4a, current CUDA dropped it, and Ollama's Vulkan path hides a lot of performance. Most of the wins here came from configuration, not from model choice.

Backend: CUDA sm_60 vs Ollama/Vulkan

CUDA 12.6 llama.cppOllama Vulkan

Generation tok/s at ctx 8192. The backend also inverts the ranking: devstral is slowest on Vulkan and fastest on CUDA. MMLU-Pro moved by one question in total, so accuracy does not depend on the backend. cuda-rerun

KV cache: f16 vs q8_0 (devstral Q8_0)

f16 @ ctx 32768q8_0 @ ctx 49152

f16 reads KV at 546 GB/s (91 % of the ceiling). q8_0 reads it at 104 GB/s, because any q8_0 in the cache puts flash attention on its slow path. Production stays on q8_0 @ 49k for the context room. bandwidth report

Split mode: layer vs tensor (2 Oct)

layer tok/stensor tok/s

llama-bench tg128, f16 KV, flash attention on, 3 reps. Tensor split hangs (both cards at 100 % and 37 W) until NCCL_P2P_DISABLE=1 sends the all-reduce through host memory. The driver reports P2P as OK, but GPU1 sits in a Gen3 x4 slot behind the Ryzen root complex. Prefill gains 50–60 % too, and VRAM is unchanged. p100-optimize

Speculative decoding on planner edits (qwen3.8-27b)

Decode tok/s on 5 planner-bench tasks, temperature 0, grammar on, all correct. MTP accepts ~99 % of drafts here against 77 % on general prompts in round 2, because the plan is mostly a copy of the input file. "MTP 4" = up to 4 drafted tokens; it only fits 2×16 GB with -ub 256. DFlash crashes under tensor split. On the MoE planner every speculative mode tried, n-gram included, is slower (35–43 against 66 tok/s).

Tool use: tau-bench retail

A multi-turn tool-calling agent loop against the retail domain. There were 0 parse failures across 375 tasks and ~4,000 model calls on four architectures, so tool-call emission is solid and every failure was reasoning or policy.

PassCeiling: stalls where the model had found the right order and then asked a question
