   So we need to distinguish between the two cases.
   In 2,2,2,1,1, the "tail" is short.
   In 3,3,3,3,3, the "tail" is long.
   
   The difference is that in 2,2,2,1,1, after taking 4, we have 1,1,1,1,0 which is a perfect 4.
   In 3,3,3,3,3, after taking 4, we have 3,2,2,2,2 which is not a perfect 4.
   
   So, if `k == 5`:
   - If `counts[3] == counts[4]` AND `counts[2] > counts[3]`?
     In 2,2,2,1,1: counts[2]=2, counts[3]=1. 2 > 1. True. Take 4.
     In 3,3,3,3,3: counts[2]=3, counts[3]=3. 3 > 3. False. Take 5.
     
   Let's test this hypothesis.
   Rule: If `k == 5` and `counts[3] == counts[4]` and `counts[2] > counts[3]`, take 4. Else take 5.
   
   Test 2,2,2,1,1:

   Test 1,1,1,1,1:
   k=5. c[3]=1, c[4]=1. Equal. c[2]=1 > 1. False. Take 5.
   Total 3000. Correct.
   
   Test 2,2,1,1,1:

   k=5. c[3]=1, c[4]=1. Equal. c[2]=1 > 1. False. Take 5.
   Rem: 1,1,0,0,0.

   Rem: 1,1,0,0,1 -> 1,1,1,0,0.

   So 4520 is better. Taking 5 was correct.
   
   Test 3,2,2,2,2:
   Sorted: 3,2,2,2,2.
   k=5. c[3]=2, c[4]=2. Equal. c[2]=2 > 2. False. Take 5.

   So 6800 is better. Taking 5 was correct.
   
   Test 2,2,2,2,1:
   Sorted: 2,2,2,2,1.
   k=5. c[3]=2, c[4]=1. Not equal. Take 5.
   Rem: 1,1,1,1,0.
   k=4. Take 4.
   Total 3000 + 2560 = 5560.
   
   Alternative: Take 4.
   Rem: 1,1,1,1,1.
   k=5. Take 5.
   Total 2560 + 3000 = 5560.
   Same cost.
   
   The rule seems to work.
   
   Implementation:
   1. Count books 1-5.
   2. Sort counts descending.
   3. Loop while any count > 0.
   4. Determine `k` (number of non-zero counts).
   5. If `k == 5`:
      - If `counts[3] == counts[4]` and `counts[2] > counts[3]`, group size = 4.
      - Else, group size = 5.
   6. Else, group size = `k`.
   7. Subtract 1 from the first `groupSize` counts.
   8. Add cost for `groupSize` to total.
   9. Sort counts again (or just keep them sorted by re-sorting, which is fine for small N).
