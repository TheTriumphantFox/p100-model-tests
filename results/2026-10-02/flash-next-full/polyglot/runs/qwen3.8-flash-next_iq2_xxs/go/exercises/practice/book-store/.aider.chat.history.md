The algorithm involves:
1. Counting the frequency of each book title (1-5).
2. Sorting these frequencies to process them efficiently.
3. Iteratively forming groups of books to maximize discounts. The key insight is that a group of 4 books (20% discount) is often better than a group of 5 (25%) and a group of 1 (0%) combined, or two groups of 4 vs one group of 5 and one group of 3. Specifically, 2 groups of 4 is cheaper than 1 group of 5 and 1 group of 3.
   - Cost of 1 book: 800
   - Cost of 2 books: 1520 (2 * 800 * 0.95)
   - Cost of 3 books: 2160 (3 * 800 * 0.90)
   - Cost of 4 books: 2560 (4 * 800 * 0.80)
   - Cost of 5 books: 3200 (5 * 800 * 0.75)
   
   Note: 2 groups of 4 = 2 * 2560 = 5120.
   1 group of 5 + 1 group of 3 = 3200 + 2160 = 5360.
   So, we should prefer forming groups of 4 if possible, especially when it avoids leaving small remainders that don't benefit much from discounts.

   A greedy approach works well here:
   - Sort counts descending.
   - While there are books left:
     - Take the largest group size possible (up to 5 distinct books).
     - Actually, the standard greedy strategy for this specific problem (often called the "Bowling Green" or similar discount problem) is to try to form groups of 5, then 4, etc., but checking if splitting a 5+3 into 4+4 is better.
     - A simpler recursive or iterative approach:
       - Calculate counts for each book type.
       - Sort counts.
       - While total books > 0:
         - Find the number of distinct books available (non-zero counts). Let this be `k`.
         - If `k` == 0, break.
         - Calculate cost for a group of size `k`.
         - Subtract 1 from the `k` largest counts.
         - Add cost to total.
         - BUT: We must check if replacing a group of 5 and a group of 3 with two groups of 4 is better.
         - Actually, the optimal strategy is:
           - Form as many groups of 5 as possible? No.
           - Let's look at the counts.
           - If we have counts like [2, 2, 2, 1, 1] (sorted desc: 2,2,2,1,1).
           - Greedy: Take 5 distinct -> cost 3200. Remaining: [1,1,1,0,0] -> 3 distinct -> cost 2160. Total 5360.
           - Optimal: Two groups of 4.
             - Group 1: 1,1,1,1 (from the 2s and 1s? No, distinct titles).
             - The example says: 2 copies of 1st, 2nd, 3rd, 1 copy of 4th, 5th.
             - Counts: 2, 2, 2, 1, 1.
             - Strategy 1: One group of 5 (1,2,3,4,5) + One group of 3 (1,2,3). Cost: 3200 + 2160 = 5360.
             - Strategy 2: Two groups of 4.
               - Group 1: 1,2,3,4. Remaining: 1,1,1,0,1 -> 1,1,1,1.
               - Group 2: 1,2,3,5. Remaining: 0,0,0,0,0.
               - Cost: 2560 + 2560 = 5120.
             - So we need to check if we can improve the greedy "largest group first" by splitting larger groups into smaller optimal ones.
             - Specifically, if we have a group of 5 and a group of 3, check if two groups of 4 is cheaper.
             - Generally, we can just calculate the cost for all possible groupings using a recursive function or dynamic programming, but a greedy approach with a check for the 5+3 vs 4+4 case is often sufficient for this specific problem size (5 books).
             - Actually, a simpler greedy works:
               - While there are books:
                 - Count how many distinct books have count > 0. Let this be `n`.
                 - If `n` == 0, break.
                 - If `n` == 5, check if we have at least 3 books with count >= 1 (which we do if n=5). Wait, the check is: if we have a group of 5 and a group of 3, is it better to have two groups of 4?
                 - This logic is complex to implement in a simple loop.
                 - Alternative: Recursive function `calculateCost(counts)`.
                   - Find max count `m`.
                   - Try all possible group sizes `k` from 1 to 5 (where `k` <= number of non-zero counts).
                   - Actually, standard solution:
                     - Sort counts.
                     - While sum(counts) > 0:
                       - Find number of non-zero counts `n`.
                       - If `n` == 0, break.
                       - If `n` == 5, check if we can form two groups of 4 instead of one 5 and one 3?
                       - Actually, the optimal strategy is:
                         - While there are books:
                           - Let `n` be the number of distinct books with count > 0.
                           - If `n` == 0, break.
                           - If `n` == 5, check if we have at least 3 books with count >= 1? No, check if forming a group of 5 is worse than forming groups of 4s.
                           - Actually, the rule is: if we have a group of 5 and a group of 3, compare cost(5)+cost(3) vs 2*cost(4).
                           - 3200 + 2160 = 5360. 2 * 2560 = 5120. 5120 < 5360. So prefer 4+4.
                           - So if we have 5 distinct books and at least 3 of them have count >= 2? No, just if we can form a group of 5 and a group of 3, check if two groups of 4 is better.
                           - Actually, simpler: just try all combinations of groups.
                           - Since there are only 5 books, we can just use a recursive function that tries to take a group of size `k` (1 to 5) from the current counts and recurses.

package bookstore

import "sort"

func Cost(books []int) int {
	if len(books) == 0 {
		return 0
	}

	// Count occurrences of each book
	counts := make([]int, 5)
	for _, book := range books {
		if book >= 1 && book <= 5 {
			counts[book-1]++
		}
	}

	// Sort counts in descending order
	sort.Sort(sort.Reverse(sort.IntSlice(counts)))

	return calculateCost(counts)
}

func calculateCost(counts []int) int {
	// Remove trailing zeros to find effective number of distinct books
	n := 0
	for _, c := range counts {
		if c > 0 {
			n++
		}
	}

	if n == 0 {
		return 0
	}

	// Try forming a group of size k, where k is the number of distinct books available
	// We want to maximize discount, so we try the largest group first in the greedy approach,
	// but since we are recursive, we can just try all valid group sizes and take the min cost.
	// Actually, the greedy approach of taking the largest possible group is optimal IF we handle the 5+3 vs 4+4 case.
	// Let's use the recursive approach: try all possible group sizes k from 1 to n.
	
	minCost := 0
	// Initialize with a large number
	minCost = 1 << 30

	for k := 1; k <= n; k++ {
		// Create a copy of counts and decrement the top k counts
		newCounts := make([]int, 5)
		copy(newCounts, counts)
		
		for i := 0; i < k; i++ {
			newCounts[i]--
		}
		
		// Calculate cost for this group of size k
		groupCost := groupCost(k)
		
		// Recursively calculate cost for the remaining books
		remainingCost := calculateCost(newCounts)
		
		total := groupCost + remainingCost
		if total < minCost {
			minCost = total
		}
	}

	return minCost
}

func groupCost(n int) int {
	switch n {
	case 1:
		return 800
	case 2:
		return 1520 // 2 * 800 * 0.95
	case 3:
		return 2160 // 3 * 800 * 0.90
	case 4:
		return 2560 // 4 * 800 * 0.80
	case 5:
		return 3200 // 5 * 800 * 0.75
	default:
		return 0
	}
}
